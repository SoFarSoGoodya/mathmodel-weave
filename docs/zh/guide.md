# 使用说明

在一个 Codex 主会话中打开 `mathmodel-weave`，直接告诉操作助手要做什么。你不需要记住一长串命令或手动协调多个会话；助手按仓库说明运行现有 CLI、解释已保存状态，并在必须由你决定时询问。

这里有两类 AI，请不要混淆：

- 你正在交谈的 Codex 项目会话是“操作助手”，负责检查环境、操作 case、记录你的原话和分发任务。
- 项目内部的“受管建模 agent”负责路线探索、审阅和分析。它们的任务、权限和结果由项目保存，不等同于当前聊天。

新的操作助手会话不会自动知道此前的研究聊天，也不能重建丢失的 provider 对话；它不会自动配置你的电脑。它只是阅读本项目内的说明并调用已经存在的工具。项目没有常驻聊天服务，也不会自动监听你修改的文件。

## 第一次使用前

你需要 Linux 或 WSL、一个可用的 Codex 账号，或者已由你配置好的兼容 provider。登录和密钥只放在可信的本机 Codex 登录或用户配置中；不要把密码、令牌或密钥发进聊天，也不要写入人工回答文件。

依赖检查由项目自带的 `doctor` 完成，不需要先调用模型。它不验证实时 provider、模型可用性、MCP 或 session 恢复成功。case 模板里的历史模型名需要对照你的实际账号配置核对。操作助手可以替你运行检查、解释缺什么，并准备安装步骤；涉及登录、管理员密码或系统安装时，它必须先请你操作或确认，不能承诺完全无人参与。

如果你的账号确实提供 Luna，可以把 Luna 配合 medium 用于轻量的安装引导和状态解释；这不是强制要求，也不能假定每个账号都可用。复杂建模仍应使用适合任务的模型。助手不得悄悄换成另一个模型别名。

## 打开项目并开始

在一个 Codex 主会话中打开 `mathmodel-weave` 产品项目，然后复制下面这段话：

> 请先阅读 AGENTS.md、docs/zh/guide.md；需要具体命令时再查 docs/zh/setup.md 和 docs/zh/cli.md。请运行现有 doctor 检查环境，简明告诉我缺少什么，并在本项目内使用现有工具完成初始化和后续操作。需要登录、管理员权限、真实档位选择、路线或结果选择、披露确认、最终提交包批准时，请先问我，不要替我作决定或编造回答。

你需要提供：题目原文件、数据文件、目标、可用资源、限制条件，以及关键节点上的真实选择。助手负责：运行检查与初始化、整理文件、展示需要你看的内容、记录你的原话、启动受管任务、汇总状态和定位故障。

## 每道新题怎样开始

把原始 PDF 和 XLSX 放在 Linux/WSL 能读取、你自己容易找到的普通文件夹中，最好每道题单独一处，并保留原文件不改。把文件路径告诉操作助手，它会建立新的 case、导入材料并保存工作副本。

导入后，你主要检查校正后的题目文字，不需要逐行检查每个工作表。请重点核对页码、单位、公式、表格标题、变量含义和约束；若你直接修改了题目 Markdown，随后告诉助手：“已更新，请读取最新内容。”助手会读取并记录差异，不能声称它自动看到了修改。

开始研究前，请告诉助手：你想解决的目标、可用时间与计算资源、必须遵守的条件，以及你倾向的思路。然后明确选择一个档位：

- fast：快速摸清方向，适合时间很紧或先做初探。
- standard：通常适合完整的日常建模流程，可以作为建议，但必须由你明确同意。
- full：用于困难推导、更多路线或关键复核，通常更耗时。

三档绑定人工授权与所选 profile 设置，本身不保证固定路线数或硬 token/cost/deadline 上限。批准对象包含题面哈希和 profile model/effort；题面或 model/effort 改变时，需要通过现有流程取得新的真实决定。选择一次档位后，授权范围内的普通实验、重算和代码迭代可以连续进行，不必每次询问。若范围、权限或重要预算发生有意义的变化，助手仍要重新向你说明并获得同意。

你的想法可以成为一条独立候选路线，但不是不可质疑的命令。受管 agent 可以指出问题；除非不同路线真正得到同一结论，否则不能为了迎合而把它们提前合并。你会看到清楚的备选方案及比较，可以选择其中一个、要求融合成新方案，或者全部否决。融合是新的候选，仍需单独审阅。

## 什么时候需要你参与

| 什么时候 | 你会看到什么 | 你要做什么 |
| --- | --- | --- |
| 新题开始 | 导入摘要、校正后的题目和 fast/standard/full 说明 | 核对题意，补充目标、资源和约束，明确选择档位 |
| 题目存在真正歧义 | 不能从原文可靠判断的问题与可能解释 | 给出你的解释，或要求暂缓；不要让助手猜成“人工决定” |
| 路线或结果选择 | 独立方案、优缺点、实验结果和比较 | 选择、要求融合，或否决并说明原因 |
| 权限或重要预算要变化 | 变化内容、原因和影响 | 明确同意或拒绝；没有答复时操作方应等待 |
| 论文草稿审阅 | 实际采用了哪些 AI 内容、人工怎样修改与核验 | 只确认真实披露事实；缺失内容可以先暴露，但成稿前必须补全 |
| 最终提交前 | 完整论文、AI 使用详情和待批准的整个包 | 检查最终文件，明确批准或拒绝这个完整版本 |

受管工作流提出的问题写在当前 case 的 `human/AI_QUESTIONS.md`，你的原话写在 `human/HUMAN_ANSWERS.md`，决定由现有工具记入同一 case 的控制记录。你可以直接在 Codex 聊天中回答，并说：“请按我的原话记录到当前问题”；操作助手会使用现有命令完成记录。你也可以自己编辑回答文件，然后说：“已更新，请读取最新内容。”

回答可以很短，例如：

> 对当前路线选择问题：我选择方案 B，因为它满足时间限制；保留方案 A 作为敏感性分析，不批准其他融合。

这不是 mmagent 内置的自然语言聊天界面，也没有自动文件监视。当前 Codex 会话只是替你操作现有 CLI；受管任务只会读到已经保存并绑定到当前问题的回答。没有真人答案时，助手和 operator 必须等待，不能代填。

## 隔天继续、暂停或换系统

不要新建另一个同名 case。重新打开本项目后，把下面这段话发给操作助手：

> 请读取 AGENTS.md 和 docs/zh/guide.md，检查我的原 case、已保存状态与产物，先告诉我停在哪里；保留任务/attempt/证据和有效决定，在授权范围内接续。请区分操作助手聊天丢失与受管 provider session 丢失；历史不可用时，说明怎样在新任务/新 session 中接续选定产物，不要假装找回了原会话。缺少真实选择时直接问我，不要代填。

如果你知道 case 名称，也一并告诉它。等待期间不需要让模型空转；等你回来后再读取状态并继续。

重新打开的是**操作助手主聊天**：它可以仅凭仓库 Markdown 与 case 文件继续操作，不需要此前聊天。受管 agent 的 `resume` 不同，需要保存的 provider session 仍然可访问。SQLite 只记录 session ID 和 attempt 事实，不包含 provider 的完整对话；日志与输出保留证据，但不保证包含全部旧聊天。

换系统后，Git 独立恢复产品研发；恢复业务 case 则需要另行备份的完整目录，包括隐藏 runtime 状态、输入、workspace、日志、产物、人工记录和论文文件。runtime 路径是绝对路径，应把 case 恢复到原位置。当前没有 rebase 或原地替换 session 的 CLI。历史丢失时保留旧 task/attempt/输出，用不同 task ID 和新的 session 显式接续选定材料；不能反复恢复不存在的会话或抹去旧记录。原 case 路径无法恢复时，保留旧 case 作证据，初始化新 case 并显式导入；决定与依赖不会自动转移。具体边界见[环境配置](setup.md)和[开发交接](dev.md)。

遇到故障时，直接说现象即可，例如：“刚才中断了，请查看当前 case 的状态和日志，解释原因；在需要登录、管理员权限或改变范围前先问我。”助手会检查保存的状态和日志。认证、限流、传输中断或暂停不应通过重复创建任务来掩盖；原历史仍可访问时按原 session 恢复。不得手改 SQLite 隐藏历史不可用的事实。

## 最后检查与导出

论文完成后，请检查 case 的出版输出目录中的电子论文、AI 工具使用详情和页面审阅材料。编译成功不等于视觉审阅，已审阅的包也不等于人工批准。让操作助手告诉你本次确切路径并打开或列出文件，不需要自己理解哈希、清单或内部引用格式。

最终批准针对的是当时完整且内容固定的整个包，不是“以后随便修改的论文”。批准后若任何文件改变，必须重新生成待审包并重新确认。通过验证的导出会保存到你指定的新目录；请让助手明确回报实际导出位置，再从那里复制提交文件。

项目自带的 synthetic allocation 示例只是离线合成演示，用来展示 greedy 与 exhaustive 的流程和论文形态。它不是真实竞赛题，也不包含真实参赛者的路线、披露或最终批准。开始真实题目时应建立新的 case，使用当年题目、数据、适用的竞赛/赛区规则、真实人工决定和真实 AI 使用事实；每个 case 都必须重新获取并冻结适用规则。

需要了解所有环境要求、命令、文件路径或故障细节时，再让助手查阅 [环境配置](setup.md) 和 [命令参考](cli.md)。实际实现与验证边界见[当前状态](status.md)，系统结构见产品根目录的 [README](../../README.md)。
